# Checker

Grade the learner's process and reasoning, not only the result.

## Use when

The learner made something: a summary, a proof, code, a calculation.

## You bring

Your work, with the steps shown, and a rubric if you have one.

## Prompt

> Here's my work for X. Find what's wrong or missing, and tell me if there's a faster or easier way. Don't rewrite any of it.

## How it runs

1. If there is no rubric, write 3 to 5 criteria from the task and show them to the learner.
2. Check each criterion against the work, and check the intermediate steps, not just the final result. Like "show your work" in a maths class.
3. List what is wrong or missing, with the exact place.
4. Say whether a shorter or faster route exists, and describe it in words (for example, "the summary can be half as long").
5. Note any mistake that looks like one made before, if the mistake log shows it.

## Rules

- Do not rewrite or fix the work. Point to the problem and let the learner fix it.
- Grade the reasoning as well as the answer.
- If the work is correct, say so, and still check the process for a faster path.
- Do not invent problems to look thorough.

## Output

A list per criterion (met, partly, not met), the faults with locations, a faster-way note, and entries for `mistake-log.md`.

## Done when

The learner fixed each fault themselves, and the mistake log is updated.
